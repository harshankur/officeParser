Format Deep Dives

Reading the Spreadsheet You See, Not the One Stored

Type 19% into a cell and the file stores 0.19 and a note on how to show it. Which one is the content? Both, and every writer needs a different half.

HA
Harsh Ankur
Published 26 October 2026 · 6 min read

Type 19% into a spreadsheet cell and save the file. What is in the file is not "19%". It is 0.19, and a note elsewhere that says to show it as a percentage. A date is a count of days. Thirty hours is the number 1.25. A row you hid is still there, with a flag on it.

So which is the cell's content: what the file stores, or what the sheet shows? For years officeParser gave the stored value and nothing else, which is right for a CSV and wrong for a printout: a PDF of a budget that says 0.19 where everyone saw 19% is not the budget. In 8.3.0 a cell carries both, and every writer takes the one its format needs.

What an XLSX Cell Holds

I built a small workbook by hand, writing the XML myself so I knew exactly what was in it. One sheet, a label in column A and a value in column B. Here is the percentage, as the sheet stores it: 

<c r="B1" s="1"><v>0.19</v></c>

The s="1" is the only clue. It points into the workbook's list of cell styles, whose second entry says numFmtId="9", one of Excel's built-in formats: 0%. Formats of your own get numbers from 164 up and their code written out in the styles part: 

<numFmt numFmtId="164" formatCode="#,##0.00 [$€-407]"/>
<numFmt numFmtId="165" formatCode="dd.mm.yyyy"/>
<numFmt numFmtId="166" formatCode="#,##0.00;(#,##0.00)"/>
<numFmt numFmtId="169" formatCode="[h]:mm"/>

A format code is a small language. Sections split by semicolons are for positive numbers, negative numbers and zero, so #,##0.00;(#,##0.00) shows a debt in brackets without its minus sign. [$€-407] is a currency symbol with a locale tag. m is a month, unless it stands next to an hour or a second, when it is a minute. [h] counts hours past a day.

Both Halves of a Cell

officeParser reads each cell's stored value into its text, as before, and puts beside it what the sheet shows (shownText), what kind of value it is (valueType), the value in full where the text is something else (value), and the format code (numberFormat). A hidden row's cells are marked hidden. 

import { parseOffice } from 'officeparser';

const ast = await parseOffice('report.xlsx');
const sheet = ast.content.find(node => node.type === 'sheet');
for (const row of sheet.children) {
    for (const cell of row.children) console.log(cell.text, cell.metadata);
}

For the value column, that prints (the labels left out): 

0.19        { shownText: '19%', valueType: 'number', numberFormat: '0%' }
120         { shownText: '120.00 €', valueType: 'number', numberFormat: '#,##0.00 [$€-407]' }
2023-03-15  { shownText: '15.03.2023', valueType: 'date', value: '45000', numberFormat: 'dd.mm.yyyy' }
-1234.5     { shownText: '(1,234.50)', valueType: 'number', numberFormat: '#,##0.00;(#,##0.00)' }
06:00:00    { shownText: '6:00', valueType: 'time', value: '0.25', numberFormat: 'h:mm' }
10.456      { shownText: '10.5 kg', valueType: 'number', numberFormat: '0.0 "kg"', hidden: true }
30:00:00    { shownText: '30:00', valueType: 'time', value: '1.25', numberFormat: '[h]:mm' }
1E5         { valueType: 'text' }

A date's text is the ISO date, which every program reads the same way, and its value keeps the day count (45000 is 15 March 2023 in Excel's 1900 date system). The last cell is the reason valueType exists: 1E5 was typed as text, a part number perhaps, and a writer that guessed from the text alone would turn it into 100000.

Each Writer Takes Its Half

Having both lets every output take the half its format is for:

  • CSV, text and chunks keep the stored values. A CSV of the sheet starts Growth,0.19: a number another program can add up, not a string with a percent sign.
  • PDF prints what the sheet shows (19%, (1,234.50), 30:00) and leaves the hidden row out, as a printout does. pdfConfig.printHidden prints it.
  • XLSX output writes each format code as it was, so the value and its look survive a round trip.
  • ODS output writes the value as ODS holds one (a percentage, a currency amount, a date, a time of PT30H0M0S) with a number style built from the format code, and the shown text inside the cell, as ODS keeps it.
const pdf = await ast.to('pdf', { pdfConfig: { engine: 'native' } });                    // as seen
const all = await ast.to('pdf', { pdfConfig: { engine: 'native', printHidden: true } }); // hidden rows too

Writing the Shown Text

Excel's format codes are not a standard any library speaks, but officeParser already had an engine for something close: the template engine formats numbers and dates with Word's pictures (#,##0.00, dd.MM.yyyy). The spreadsheet reader turns what only Excel's codes hold into that language first: it picks the section for the value's sign, turns [$€-407] into its symbol, drops colours ([Red]) and locale tags, reads _) padding and * fill as a space, divides by a thousand for each trailing comma (#,##0,"K"), and decides whether each m is a month or a minute. Elapsed time ([h]:mm, [mm]:ss) it writes itself, which is how 1.25 days becomes 30:00 and not 6:00 on the next day.

What It Will Not Guess

Where a code says something officeParser cannot write the way Excel would, the cell gets no shown text and every output uses the stored value. That covers General, scientific notation (0.00E+00), fractions (# ?/?), conditions ([>=100]) and text sections. Excel's built-in date formats are left alone too, because they follow the date order of the machine that opens the file: what one reader sees as 3/15/2023 another sees as 15.03.2023, so the unambiguous ISO date is the better guess.

One more limit is easy to miss: the shown text uses a full stop for decimals and a comma for thousands. A format code says where the separators go, not which characters they are. Excel takes those from the machine's language, so a German Excel shows the price above as 120,00 €.

A spreadsheet is a table of numbers and a set of instructions for showing them. Read as one or the other, it is half a document. Read as both, a CSV can add it up and a PDF can print it as it was.

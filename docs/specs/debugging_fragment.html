Troubleshooting & Debugging

Solutions for common integration challenges and performance optimizations in officeParser v8. Node.js >= 22.13 is required.

Pro Tip
Use the onWarning callback to capture internal diagnostic information and trace logs during the parsing process. 
const config = {
    onWarning: (issue) => console.warn(`[OfficeParser] ${issue.message}`, issue.details)
};

1. Node.js Process Hanging (OCR)

When you use ocr: true (with extractAttachments: true), the library maintains a persistent worker pool to make subsequent OCR tasks much faster. However, this background pool will keep your Node.js process alive for 10 seconds of inactivity by default.

Solutions:

  • For CLI/Short-lived scripts: Call await terminateOcr() manually after your parseOffice call.
  • Change Timeout: Set a shorter idle period via ocrConfig.timeout.autoTerminate.
  • Disable Pooled Persistence: Set the auto-terminate timeout to 0 to kill workers immediately (similar to legacy behavior).
import { parseOffice, terminateOcr } from 'officeparser';

const ast = await parseOffice('scanned.pdf', { ocr: true, extractAttachments: true });
// Process finishes...
await terminateOcr(); // Snappy exit

2. PDF Rendering Issues (Browser)

If PDF parsing fails in the browser with "Worker not found" or "Version mismatch" errors:

  • Worker Source: Ensure pdfWorkerSrc points to a valid URL. By default, it uses a CDN pointing to pdfjs-dist@6.2.108.
  • Version Matching: If you host the worker locally, ensure it matches the pdfjs-dist@6.2.108 used by the library.

3. OCR Accuracy & Performance

If OCR results are missing or incorrect:

  • Language Selection: Ensure you've provided the correct language code. You can combine multiple languages with a + sign (e.g., eng+deu).
  • Air-gapped Environments: In restricted environments, tesseract.js cannot download language files. You must provide local paths via ocrConfig.workerPath, ocrConfig.corePath, and ocrConfig.langPath.
  • Memory: Parallel OCR on many images can be intensive. officeParser limits the pool to 4 concurrent workers by default to prevent crashes.

4. Memory Management (Giant Files)

When parsing extremely large Excel (.xlsx) or PowerPoint (.pptx) files:

  • AST vs. Text: The structured AST consumes significantly more memory than plain text. If you don't need the hierarchy, use await ast.to('text') and allow the AST to be garbage-collected immediately.
  • Ignore Notes: For complex PowerPoints, setting ignoreNotes: true can reduce memory usage by skipping entire XML trees.

5. Metadata & Custom Properties

If metadata.customProperties is empty:

  • metadata.customProperties is populated for OOXML (DOCX, XLSX, PPTX), ODF (ODT, ODS, ODP, ODG), PDF, and LaTeX (the custom pdfinfo keys of \hypersetup).
  • HTML and Markdown expose their <meta> tags / YAML front matter as metadata.nativeProperties rather than customProperties; EPUB exposes its OPF metadata. Legacy RTF supports no custom-property extraction.

6. Bundle Selection

Ensure you are importing the correct build for your environment:

  • Node.js (CJS/ESM): Standard import or require works automatically via package.json exports.
  • Modern Bundlers (Vite/Webpack): Use the .mjs bundle for best treeshaking.
  • Legacy Browser Scripts: Use dist/officeparser.browser.iife.js for a global officeParser namespace.

7. Text-Based Buffer Detection Failure (IMPROPER_BUFFERS)

When passing a Buffer or ArrayBuffer for md, html, csv, or tex files, the parser cannot auto-detect the format, since these formats have no magic bytes. You must provide a fileType hint: 

// Without fileType → throws IMPROPER_BUFFERS
await officeParser.parseOffice(markdownBuffer);

// Correct:
await officeParser.parseOffice(markdownBuffer, { fileType: 'md' });
await officeParser.parseOffice(htmlBuffer,     { fileType: 'html' });
await officeParser.parseOffice(csvBuffer,      { fileType: 'csv' });
await officeParser.parseOffice(latexBuffer,    { fileType: 'tex' });

ZIP-backed formats do not need this hint. DOCX, XLSX, PPTX, ODT, ODS, ODP and EPUB are all ZIP archives, and identifying them from the leading bytes alone is unreliable for archives written by streaming producers (which defer entry sizes to trailing data descriptors) or holding very many parts. When the byte signature comes back as a plain zip, the archive is opened and the format is read from its own declaration, either [Content_Types].xml or the mimetype entry. If you previously saw Sorry, OfficeParser currently supports docx, pptx, xlsx… for a valid document, that was this case and it no longer occurs.

A LaTeX project zip (an Overleaf "Download source" zip, or a texConfig.bundle zip) is recognized the same way: an archive holding a .tex file with \documentclass near its root parses as tex. A file named .zip is always routed by what the archive holds, since zip itself names no format.

The fileType option is authoritative: it bypasses magic-bytes detection even for binary formats.

8. PDF Generation Fails (Node.js)

PDF output (format: 'pdf') with the default 'html' engine uses Puppeteer, which is an optional peer dependency not included by default. If generation throws a dependency error, install it:

npm install puppeteer

Alternatively, set pdfConfig.engine: 'native' to lay the document out directly with pdf-lib (its own optional peer dependency), which needs no browser and no Puppeteer.

In CI/CD environments where Puppeteer cannot download Chromium automatically, pass a custom executable path via pdfConfig.launchOptions: 

await OfficeGenerator.generate(ast, 'pdf', {
    pdfConfig: {
        launchOptions: {
            executablePath: '/usr/bin/chromium-browser',
            args: ['--no-sandbox', '--disable-setuid-sandbox']
        }
    }
});

9. ZIP Decompression Limits & Resource Protection

By default, officeParser enforces extraction limits to prevent excessive memory and CPU consumption when processing large archives (archives that expand to massive sizes or contain a very large number of files).

  • Max Uncompressed Size: Defaults to 512 MB. Files exceeding this size will reject with a ZIP_SIZE_LIMIT_EXCEEDED error.
  • Max Zip Entries: Defaults to 10,000 entries. Archives with more files will reject with a ZIP_ENTRY_COUNT_LIMIT_EXCEEDED error.
  • Corrupt / non-ZIP input: Data that yields no readable ZIP entries at all rejects with a ZIP_NO_ENTRIES_FOUND error, since every ZIP-based document format requires at least one entry. This is not a tunable limit: it means the input is corrupt, truncated, or not actually a ZIP-based file.
  • Truncated input: An archive missing its End of Central Directory record rejects with a ZIP_TRUNCATED error. The file was cut off (typically an interrupted download or upload), so entries recovered from it cannot be trusted to be the whole document.
  • Wrong kind of archive: A perfectly readable ZIP that lacks the part its format requires rejects with a REQUIRED_PART_MISSING error naming the missing part (word/document.xml, xl/workbook.xml, ppt/presentation.xml, ODF content.xml, or the EPUB OPF). This is what a renamed ZIP or a partial upload looks like.

None of these three are tunable: they report that the input is not a usable document, not that a limit was hit. A workbook with only chartsheets and a presentation with no slides are legitimate and still parse, emitting a NO_WORKSHEETS_FOUND or NO_SLIDES_FOUND warning so an empty result is never silent.

If you need to process larger files, you can increase these limits or disable them by providing custom values in decompressionLimits:

const ast = await officeParser.parseOffice('large_file.docx', {
    decompressionLimits: {
        maxUncompressedBytes: 1024 * 1024 * 1024, // 1 GB limit
        maxZipEntries: 50000 // Allow up to 50k zip entries
    }
});

10. LaTeX Input

LaTeX is a macro language, so the parser interprets it under fixed bounds rather than running it: nothing is executed, there is no shell escape, and nothing is read from the filesystem (included files and images come only from a project .zip, and paths escaping its root are refused). What it could not do is reported through onWarning / ast.warnings:

  • LATEX_FILE_NOT_FOUND: an \input/\included file or an \includegraphics image could not be read. A bare .tex contains neither, so parse the project .zip instead (with extractAttachments: true for the image bytes). Images are kept as references to their path (metadata.url).
  • LATEX_CONSTRUCT_NOT_INTERPRETED: the document uses commands or environments the parser does not interpret (a TikZ picture, for example). Text inside them is kept where there is any; drawings are omitted. The message names each construct once.
  • LATEX_EXPANSION_LIMIT_REACHED: a bound was hit (200,000 macro expansions, 5,000,000 expanded characters, which included files count toward too, 128 nested input frames, include depth 16, nesting depth 128, or 32 nested tables), so content past it was not expanded (content nested too deep is kept as plain text). Include cycles are cut the same way. The bounds are not configurable, and parsing time grows linearly with the document. The parse runs synchronously: an abortSignal is honoured before it starts and while a project zip is read, but a timer cannot interrupt a .tex being parsed.

Quick Reference

Symptom Fix
Process stays alive after script finishes Call await terminateOcr() when OCR was used
"Worker not found" in browser (PDF) Set pdfWorkerSrc to a valid URL for pdfjs-dist@6.2.108
Low OCR accuracy Verify ocrConfig.language matches the document language
Out of memory on large Excel files Call await ast.to('text') early and discard the AST to allow GC
md/html/csv/tex buffer not detected Add fileType: 'md' (or 'html', 'csv', 'tex') to config
IMPROPER_BUFFERS error No file extension and no fileType hint provided
PDF generation fails Install optional peer dep npm install puppeteer, or use pdfConfig.engine: 'native' (pdf-lib), which needs no browser
ZIP extraction failed or limit exceeded Increase decompressionLimits.maxUncompressedBytes or decompressionLimits.maxZipEntries
ZIP_NO_ENTRIES_FOUND error The input is not a readable ZIP archive at all. Verify the file and the fileType hint
ZIP_TRUNCATED error The file was cut off in transfer. Re-download or re-upload it, then compare the byte size against the source
REQUIRED_PART_MISSING error A readable ZIP that is not the document type it claims. Check the file opens in its native application, and that fileType matches what it actually is
Document parses but comes back empty Check ast.warnings for NO_WORKSHEETS_FOUND / NO_SLIDES_FOUND - the file really is empty. Corrupt input throws instead of returning empty
LaTeX images or \input files missing (LATEX_FILE_NOT_FOUND) Parse the project .zip (e.g. Overleaf's "Download source") instead of the bare .tex, with extractAttachments: true
A TikZ figure or unknown environment is missing (LATEX_CONSTRUCT_NOT_INTERPRETED) Expected: drawings are omitted and unknown constructs keep only their text. Export the figure as an image and \includegraphics it
LaTeX content stops expanding partway (LATEX_EXPANSION_LIMIT_REACHED) The document hit a macro/include bound (often a runaway recursive macro or an include cycle). Simplify the macro or remove the cycle
Images missing from generated EPUB Pass extractAttachments: true on the parse step; without it there are no image bytes for the EPUB generator to package. OfficeConverter.convert() sets this automatically.

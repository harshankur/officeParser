Generator Configuration Specification

The GeneratorConfig object controls how the AST is transformed into final output formats like HTML, Markdown, or PDF. It consists of common options and specialized sub-configurations.

A key the generator does not recognize raises UNRECOGNIZED_CONFIG_OPTION, and a value an option does not accept (a document class, paper format or margin, PDF engine, HTML stylesheet mode, Markdown dialect preset, or chunking choice) raises INVALID_CONFIG_VALUE and uses the option's default. Both appear in the result's messages as well as reaching onWarning.

Related: OfficeGenerator & ast.to() · OfficeParserConfig (the parse side) · AST structure · OfficeConverter · CLI flags

CommonGeneratorConfig

These settings apply to every generator unless specifically overridden in a sub-config.

Property Type Default Description
includeFormatting boolean true Visual Fidelity: Whether to include colors, font sizes, and text decorations (underline, strike, etc.) in the output.
generateIds boolean true Navigation: Automatically generates unique slug-based IDs for heading nodes, enabling internal anchor links. The slugs are GitHub's in every format: lowercase, the letters and digits of every script kept, punctuation left out and spaces made hyphens (version-20 for "Version 2.0").
renderMetadata boolean false Branding: If true, renders the document metadata (Title, Author, Creation Date) as a visible header block. The native PDF engine, Markdown, XLSX, ODS, PPTX and ODP do not render it.
metadataOverrides MetadataOverrides {} Output Metadata: Overrides the metadata embedded in the generated file, merged per field over ast.metadata without mutating it. See MetadataOverrides for the full field list.
includeImages boolean | 'image-only' | 'image+ocr-text' | 'ocr-text-only' | 'none' true Resources: How to render an image node. true='image-only' (embed the image, no OCR text); 'image+ocr-text' (image then its recognized/OCR text); 'ocr-text-only' (OCR text, no image); false='none' (omit). In plain-text output an image becomes an [Image: name] placeholder (plus OCR text for 'image+ocr-text'), or just the OCR text for 'ocr-text-only'. In chunks a picture is [Image: alt] for its alt text, with its OCR text, except under 'none' and 'ocr-text-only' (OCR text only). XLSX and ODS, whose cells hold no pictures, write a picture's OCR text in its place under 'ocr-text-only' and 'image+ocr-text'; PPTX and ODP write it in the picture's place under 'ocr-text-only', and under 'image+ocr-text' after a flowing document's picture slide or in a placed slide's notes.
maxInlineImageBytes number 1500000 Resources: Max decoded image size, in bytes, that is inlined as a data: URI in HTML/Markdown (the base64 URI itself is ~1/3 larger), so a scanned page cannot emit a multi-megabyte line that breaks downstream parsers. Under the default 'image-only' mode an image over the cap renders its recognized/OCR text when it has any (multi-line OCR as a fenced block in Markdown), otherwise a compact name reference; Markdown still emits the IMAGE_NOT_INLINED warning. Plain text follows the same rule. Standalone HTML inlines whatever the cap: a self-contained document has nowhere else to resolve the image from. 0 never inlines; Infinity inlines every picture within the budget below. In every mode, standalone HTML and Infinity included, the pictures one document writes inline stop at 128 MB in all (a picture is inlined at every place showing it); the rest are name references, with IMAGE_NOT_INLINED.
includeCharts boolean true Visuals: Whether to include charts. HTML draws an interactive Chart.js canvas (or, with no chartJsSrc, the chart's data as a table); DOCX, ODT and LaTeX write the chart's data as a table, PPTX and ODP a table of its data in the chart's place; plain text and the native PDF engine write its data as text; Markdown and RTF write nothing for a chart, and XLSX and ODS, whose cells cannot hold one, report it (CONTENT_NOT_REPRESENTABLE). false omits charts in every generator.
ignoreInternalLinks boolean false Cleanup: Suppresses all internal bookmarks and anchor references (the native PDF engine's links into the document too).
ignoreDefaultStyleMap boolean false Control: If true, ignores the built-in mapping of standard Word/Office styles to semantic tags.
styleMap string[] | object[] [] Semantic Bridge: Maps source styles (e.g., 'Intense Quote') to semantic tags (e.g., 'blockquote').
onNode function undefined Interception: Async callback called for every node during generation. Return false to skip, a string to override rendering, or void to proceed with default logic (mutations to node are applied).
onWarning function undefined Diagnostics: Callback for non-fatal issues encountered during generation (e.g. unsupported drawing, skipped node). Receives an OfficeIssue object.
abortSignal AbortSignal | null null Cancellation: An optional signal to abort the generation operation, checked between steps by every generator (the native PDF engine before each node it draws; XLSX and ODS before each cell and block of text; PPTX and ODP before each node a slide takes). Rejects with an AbortError.

Specialized Sub-Configurations

Format-specific settings nested under keys like htmlConfig, mdConfig, etc.

HtmlGeneratorConfig (htmlConfig)

Property Type Default Description
standalone boolean | StandaloneConfig true Controls the HTML "document envelope". true/omitted turns every part on (a full <html> shell with CSS/scripts/metadata); false turns every part off (a bare content fragment). Pass a StandaloneConfig object for granular control (see the table below).
chartJsSrc string (CDN) URL for the Chart.js script, loaded only by a page that draws a chart. '' loads none: a chart is then written as a table of its values, with a CONTENT_NOT_REPRESENTABLE warning (details.reason: 'chart'). Under allowRemoteAssets: false it is '' unless set.
containerWidth string | number 'auto' Controls the maximum width of the rendered content container. Accepts a positive number (treated as pixels), a CSS length string ('900px', '100%', '60vw'), or 'auto' (browser default). Invalid values fall back to 'auto' and emit an INVALID_CONTAINER_WIDTH warning.
customCss string '' Raw CSS string injected into the generated <style> block. Use this to override built-in styles or add document-specific rules without modifying the core generator.
injections HtmlInjectionConfig {} Granular raw HTML injection points:
  • headStart: Injected immediately after <head> (requires standalone.document + standalone.headInjections)
  • headEnd: Injected immediately before </head> (same requirement)
  • bodyStart: Injected immediately after the opening body content (applies even to a bare fragment when standalone.bodyInjections is on)
  • bodyEnd: Injected immediately before the closing body content (same)
Useful for inserting analytics scripts, custom fonts, or wrapper elements.
sourceAttributes boolean false Carry each rich node's raw source in a data-* attribute (undelimited text content), so attribute-driven consumers can rehydrate the node: data-wikilink/data-target/data-alias on wikilinks, a <span class="citation" data-key> for citations, the LaTeX in data-math, and a <div class="mermaid" data-mermaid> for mermaid, and an empty <span data-html-comment="…"> for a source comment (an editor's DOM parser discards real comments). Off by default the output is byte-identical to before, and the parser reads every shape it emits. Forced off for PDF and EPUB.
gatedEmbeds boolean false Emit a generic (non-YouTube) iframe embed as an inert <div data-embed-gated data-embed-src> placeholder that never auto-loads its src (an editor renders a click-to-load from it, and the parser reads it back to the same embed node) instead of a live <iframe>. src is scheme-checked on emit. Off by default the output (a live <iframe>) is unchanged; YouTube embeds are unaffected.
omitDefaultTextColor boolean false Omit an inline run color equal to the document default (near-black or near-white), so imported text adapts to the reader's light/dark theme instead of being pinned to black or white. Only near-black/near-white run colours are dropped; a deliberately-coloured run is emitted unchanged (Word's w:val="auto" already carries no colour). Off by default; the output is unchanged.

StandaloneConfig (the object form of standalone)

Any field left unspecified defaults to its "on" (standalone) value, so { document: false } still yields a fully styled fragment: only the <html> shell is dropped.

Property Type Default Description
document boolean true Wraps output in <!DOCTYPE html><html><head>…</head><body>…</body></html>. When false, only the inner content fragment is emitted.
metaTags boolean true Emits <title> and <meta> tags. Only meaningful when document is true.
styles 'full' | 'scoped' | 'none' 'full' How the built-in stylesheet is delivered:
  • 'full': the complete stylesheet using global selectors (body, h1, table, …), which is what standalone: true has always emitted.
  • 'scoped': the same styling, scoped under the fragment's own wrapper via CSS @scope so it cannot leak onto a host page's elements. Requires a modern engine (Chrome 118+, Safari 17.4+, Firefox 128+).
  • 'none': no stylesheet; the host page/editor/EPUB reader supplies its own.
The boolean shorthand for standalone maps true → 'full', false → 'none'.
scripts boolean true Emits the Chart.js CDN loader and spreadsheet-interactivity <script> tags. (A per-chart inline init script is content, not envelope, and is emitted regardless of this flag whenever a chart node is present.)
headInjections boolean true Applies injections.headStart/headEnd. Only meaningful when document is true.
bodyInjections boolean true Applies injections.bodyStart/bodyEnd, even when generating a bare fragment, since these wrap body content, not the document shell.
Behavior change from previous versions
standalone: false previously emitted a fragment with a global, unscoped <style> block. It now emits a genuinely bare fragment (no <style> at all), matching "every part off". If you relied on the old styled-fragment behavior, pass { document: false } instead.

MdGeneratorConfig (mdConfig)

Property Type Default Description
dialect MarkdownDialectPreset | MarkdownDialectConfig 'extended' Which real-world Markdown flavor to emit. A preset name picks a whole set of behaviours at once; an object overrides individual features on top of one. See MarkdownDialectConfig below.
fallbackToHtml boolean | FallbackToHtmlConfig true Uses raw HTML tags for features Markdown cannot express (underline, alignment, merged cells). The boolean applies uniformly; an object controls each part independently. See FallbackToHtmlConfig below.

MarkdownDialectConfig

dialect accepts either a preset name or an object. The presets:

Preset Behaviour
'extended' (default)Every feature on, GitHub-style admonitions. Byte-identical to this library's output before dialects existed, so it is the backward-compatibility anchor.
'github'GFM: > [!NOTE] admonitions, footnotes, strikethrough, native tables. No definition lists, citations, wikilinks or attribute lists.
'gitlab'GLFM: :::note fenced-div admonitions, otherwise as GitHub.
'obsidian'As GitHub, plus [[wikilinks]].
'pandoc'::: {.note} admonitions, definition lists and citations on, and attribute lists after images ('brace-inline').
'commonmark'Strict CommonMark: no admonition syntax (plain blockquote), no footnote references (inlined as parentheticals), no strikethrough, and tables forced to HTML, since CommonMark has no table syntax.

Passing an object instead overrides individual features. Every field is optional; extends names the preset that any omitted field falls back to.

Property Type Description
extendsMarkdownDialectPresetBase preset for every field left unset. Defaults to 'extended'. Note this is the base for this object, not "whatever preset was configured before": config merging replaces the whole dialect field rather than layering onto a prior string.
admonitions'blockquote' | 'fence' | 'fence-attribute' | 'none'Which admonition syntax to emit: 'blockquote' = GitHub > [!NOTE], 'fence' = GitLab :::note, 'fence-attribute' = Pandoc ::: {.note}, 'none' degrades to a bold-labelled blockquote. The flavour names 'github'/'gitlab'/'pandoc' are accepted as deprecated aliases and will be removed in the next major.
highlight'equals' | 'none'==text== highlight (Obsidian/extended flavours). 'none' falls back to an HTML <mark>/<span> per fallbackToHtml.inlineFormatting, and == stays literal on parse.
math'dollar' | 'none'$inline$ / $$block$$ delimiters, or none (content emitted bare).
tables'native' | 'html'Pipe tables, or an HTML <table>. Forced to 'html' under commonmark.
bulletListMarker'-' | '*' | '+'Marker for unordered list items.
orderedListMarker'.' | ')'1. or 1) for ordered list items.
emphasisMarker'asterisk' | 'underscore'*em*/**strong** or _em_/__strong__. An underscore marks emphasis only at a word's edge, so with 'underscore', emphasis inside a word or right next to other emphasis is written with asterisks.
definitionLists'colon' | 'none'Markdown Extra Term\n: Definition syntax. 'none' degrades to plain paragraphs.
footnotes'caret' | 'none'[^id] references with a definition block. 'none' inlines note content as a parenthetical at the reference point rather than dropping it.
citations'at' | 'none'Pandoc [@citekey] syntax. 'none' emits the key as plain [key].
wikilinks'double-bracket' | 'none'Obsidian [[Page]] / [[Page|Alias]] syntax. 'none' makes wikilinks ordinary links.
attributeLists'brace' | 'brace-inline' | 'none'{width=50% align=center} attribute lists. 'brace' writes one after an image and one on the line under a pipe table ({align=right}, where the table stands on the page). 'brace-inline' writes one after an image only, which is what Pandoc reads: it shows a list under a table as text.
strikethrough'tilde' | 'none'~~struck~~. 'none' drops the formatting.
embeds'html' | 'directive' | 'link' | 'thumbnail'How an embed node is written: 'html' (default; the <div data-youtube-video> / <iframe> block), 'directive' (a ::youtube[…]{…} / ::embed[…]{…} leaf directive; an editor round-trip form, rendered verbatim on GitHub), 'link' (a plain link), 'thumbnail' (YouTube-only clickable preview). Authority for embed form; supersedes the deprecated fallbackToHtml.embeds boolean.

Each capability is named for the syntax it selects, with an explicit 'none' to turn it off (an omitted field inherits from extends). The former boolean form of definitionLists, footnotes, citations, wikilinks, attributeLists and strikethrough is deprecated but still accepted: true maps to the syntax value, false to 'none'. Both the boolean form and the admonition flavour aliases will be removed in the next major.

// A preset by name
await ast.to('md', { mdConfig: { dialect: 'github' } });

// GitHub, but with wikilinks and asterisk bullets
await ast.to('md', {
    mdConfig: { dialect: { extends: 'github', wikilinks: 'double-bracket', bulletListMarker: '*' } },
});

FallbackToHtmlConfig

fallbackToHtml accepts a boolean, which applies uniformly, or an object controlling each part independently. Omitted fields default to on, except inlineFormatting, which is off by default even when the boolean is true and must be opted into explicitly.

Property Type Controls
textFormattingboolean<u>, <sub>, <sup> for underline/subscript/superscript.
alignmentboolean<div align> wrappers for paragraph and image alignment.
anchorsboolean<a id> anchors for internal link targets.
tablesboolean<table> for nested or merged-cell tables a pipe table cannot express. When off, nested tables are hoisted out and rendered sequentially.
embedsbooleanDeprecated (removed next major): use dialect.embeds instead. When dialect.embeds is unset this is still honored: true maps to 'html', false to 'link'.
cellLineBreaksboolean<br> inside a table cell, which a pipe table cannot otherwise contain.
itemLineBreaksboolean<br> joining the paragraphs of a multi-paragraph list item, which stays on the item's single Markdown line, and the line breaks of a heading or a definition list's term or description, each one Markdown line too. When off, they are joined with a space.

Enable it explicitly with fallbackToHtml: { inlineFormatting: true }.

PdfGeneratorConfig (pdfConfig)

[!IMPORTANT] Two engines. The default 'html' engine renders through a headless browser (Puppeteer in Node.js, the browser's own print engine in-page) for maximum fidelity. The 'native' engine lays the AST out directly with pdf-lib (an optional peer dependency), no browser required, so it runs unchanged in Node and the browser and is the only way to produce a real PDF client-side. It honors the shared includeImages/​onNode options and the page options below, and draws a clean reflow rather than a pixel match: in the Standard-14 fonts, or in font files you give it (fonts, fallbackFonts), which any script needs past Latin. It lays text out in a section's columns, and draws an SVG picture as vector graphics in its place (paths, shapes, text, embedded PNG and JPEG pictures, fills, strokes, dashes and opacity, styled by attributes, style and the picture's own stylesheet); a gradient is drawn in one colour, and filters, masks, clip paths and patterns are left out, both reported (CONTENT_NOT_REPRESENTABLE, details.reason: 'svg'). In the prebuilt browser bundle pdf-lib is stubbed so the bundle stays self-contained; for client-side native PDF, import from the dedicated entry officeparser/browser-native-pdf and install pdf-lib.
Property Type Default Description
engine 'html' | 'native' 'html' Rendering engine. 'html' uses a headless browser (Puppeteer in Node, in-page print in the browser) for fidelity; 'native' lays out directly with pdf-lib, no browser, runs in Node and the browser, drawing in the Standard-14 font families or the font files given below.
fonts { regular?, bold?, italic?, boldItalic?, mono? } of Uint8Array | ArrayBuffer (none) Native engine: the font file (.ttf, .otf, .woff or .woff2 bytes) each style is drawn in; a WOFF or WOFF2 file is embedded as the TrueType or OpenType font it holds. A style given none is drawn in regular; code stays in Courier unless mono is given. Words are shaped by the font (ligatures, Arabic joining, Indic conjuncts), and a right-to-left line starts at the right edge. A font that cannot be read (a damaged one, a collection such as a .ttc), or whose glyphs to be drawn cannot be read or written into the PDF, fails the conversion (PDF_GENERATION_FAILED). Needs the optional peer dependency @pdf-lib/fontkit.
fallbackFonts (Uint8Array | ArrayBuffer)[] [] Native engine: more font files (TrueType, OpenType, WOFF, WOFF2), tried in order for each character the fonts before them lack, so one document can mix scripts. Given without fonts, text stays in the Standard-14 fonts and these draw only what those lack. A character is drawn by a font that has a glyph of outlines for it: the Standard-14 fonts have no ₹ (U+20B9), ₽ (U+20BD) or emoji; of Fontsource's files, Noto Sans has both signs in its latin-ext file and neither in its latin one, and Noto Sans Devanagari has ₹ but not ₽. Emoji are drawn by a monochrome font of outlines such as Noto Emoji; a color emoji font (Noto Color Emoji, Apple Color Emoji) is drawn from color images or layers the engine does not draw, so its emoji are counted with the characters no font has, and a color font none of whose characters has an outline is reported (INVALID_CONFIG_VALUE) and not used.
subsetFonts boolean true Native engine: embed only the glyphs used of each font given; false embeds whole fonts (a WOFF or WOFF2 file as the font it holds). An OpenType font of CFF outlines, or a font with color layers (COLR), is embedded whole either way.
tagged boolean true Emit a tagged, PDF/UA-accessible PDF (structure tree). HTML engine only; the native engine ignores it.
outline boolean false Emit a bookmark outline from the document's headings, nested by heading level. Both engines.
format PaperFormat 'auto' Paper format ('A4', 'Letter', 'Legal', 'A3', 'Ledger', etc.). 'auto' is the document's own pages (metadata.pageSetup; the native engine gives each section and sheet its own and takes unset margins from the document), else A4.
width string | number '' Paper width, accepts values labeled with units (e.g., '5in', '3cm') or numbers (in pixels).
height string | number '' Paper height, accepts values labeled with units (e.g., '5in', '3cm') or numbers (in pixels).
landscape boolean false Landscape page orientation.
printBackground boolean true Whether to print CSS background graphics.
margin object {0,0,0,0} Page margins: { top, right, bottom, left } in inches or mm.
displayHeaderFooter boolean false Enables PDF native headers/footers.
headerTemplate / footerTemplate string '' HTML template strings for print header/footer.
scale number 1 Rendering scale factor.
launchOptions object headless defaults Puppeteer launch options (e.g. executablePath, args). Useful for CI/CD environments.
timeout number 30000 Timeout: The PDF rendering timeout in milliseconds. Set to 0 to disable.
printHidden boolean false Print hidden sheets, rows and columns, which a printout leaves out. Both engines.
printSpeakerNotes boolean false Print each slide's speaker notes after it; a printout leaves them out. Both engines.

DocxGeneratorConfig (docxConfig)

Writes a real WordprocessingML package (a .docx ZIP) from any parsed source and returns a Uint8Array. Adds no dependencies (built on the bundled fflate), runs identically in Node and the browser, and produces reproducible bytes (honoring metadataOverrides.modified). Reproduces headings, styled runs, tables with merged cells, nested lists, images, hyperlinks, footnotes/endnotes, comments, headers/footers and metadata.

Property Type Default Description
format PaperFormat 'auto' Page size for the document section (w:pgSz). 'auto' is the document's own page (metadata.pageSetup), else A4; or the names pdfConfig.format accepts (A4, Letter, Legal, A3, Tabloid, Ledger, …; case-insensitive).
landscape boolean false Landscape orientation (swaps page dimensions and sets w:orient).
margin object the document's, else 72 Page margins (top, right, bottom, left). Each is a number of points (1/72 inch) or a unit string ('1in', '2cm', '36pt'). A side left unset is the document's own margin under format: 'auto', else 72 (one inch).

OdtGeneratorConfig (odtConfig)

Writes a real OpenDocument Text package (a .odt zip) from any parsed source and returns a Uint8Array. Adds no dependencies (built on the bundled fflate), runs identically in Node and the browser, and produces reproducible bytes. It is the round-trip partner of the ODF parser: headings, styled runs, tables with merged cells, nested lists, images, hyperlinks, footnotes, comments and headers/footers all re-parse. Formatting lives in ODF automatic styles.

Property Type Default Description
format PaperFormat 'auto' Page size for the page layout (style:page-layout). 'auto' is the document's own page, else A4; or the names pdfConfig.format accepts (A4, Letter, Legal, A3, Tabloid, Ledger, …; case-insensitive).
landscape boolean false Landscape orientation (swaps page dimensions and sets style:print-orientation).
margin object the document's, else 72 Page margins (top, right, bottom, left). Each is a number of points (1/72 inch) or a unit string ('1in', '2cm', '36pt'). A side left unset is the document's own margin under format: 'auto', else 72 (one inch).

XlsxGeneratorConfig (xlsxConfig)

Writes an Excel workbook (a .xlsx zip) and returns a Uint8Array. Adds no dependencies and runs identically in Node and the browser. A spreadsheet (XLSX, ODS, CSV) is written sheet for sheet: each cell's value typed (numbers, percentages, currency amounts, dates and times) and shown in its number format (read from CellMetadata.shownText), header cells bold, merged cells merged, and hidden sheets, rows and columns hidden. A sheet's stored numbers stay numbers, exponents and all (1E-10). Any other document is written as its tables, each on a sheet named after the heading before it (else Table 1, Table 2, ...), with its cells typed from their text: 1,250.5 is a number, 19% a percentage, €1,250.00 a currency amount (($80.00) a negative one), 2026-10-01 a date, 14:05 a time. A code with leading zeros (007), a number with a leading plus (+4915112345678) or a number of more than fifteen digits (a card number, which a spreadsheet would round) stays text, and a whole number of twelve or more digits is shown in full. The document's paragraphs, headings and list items outside its tables go on a sheet named Text, one a row, headings bold. Footnotes, endnotes, comments and speaker notes go on a sheet named Notes after the others (Footnote 1, Endnote 1, Comment (author), Slide 2, each beside its text), and the text cites each note by its label there ([Footnote 1]). A chart is a sheet of its data (its labels down, its series across), a list item keeps its marker, and an embedded video or page is its address. XLSX holds at most 32,767 characters in a cell: a longer one is cut there and reported. Pictures, which a cell cannot hold, are reported with CONTENT_NOT_REPRESENTABLE, their alternative text written in their place (their recognized text under includeImages: 'ocr-text-only', both under 'image+ocr-text'); a chart without its data is reported too (not where includeCharts is false); a document with neither a table nor text is written as one empty sheet, and reported.

Property Type Default Description
sheetPerTable boolean true Each of a document's tables on a sheet of its own. false puts them all on one sheet named Tables, an empty row between them. No effect on a spreadsheet, whose sheets are written as they are.
includeText boolean true A document's text outside its tables on a sheet named Text. false leaves it out. No effect on a spreadsheet.

OdsGeneratorConfig (odsConfig)

Writes an OpenDocument spreadsheet (a .ods zip) from the same workbook as XLSX output, with the same options, and returns a Uint8Array: a spreadsheet sheet for sheet, any other document as its tables and its text, each cell typed (office:value-type float, percentage, currency, date or time, with the text the cell shows beside its value).

Property Type Default Description
sheetPerTable boolean true Each of a document's tables on a sheet of its own. false puts them all on one sheet named Tables, an empty row between them. No effect on a spreadsheet, whose sheets are written as they are.
includeText boolean true A document's text outside its tables on a sheet named Text. false leaves it out. No effect on a spreadsheet.

PptxGeneratorConfig (pptxConfig)

Writes a PowerPoint presentation (a .pptx zip) and returns a Uint8Array. Adds no dependencies and runs identically in Node and the browser. What the slides hold depends on the source:

  • A presentation (PPTX, ODP) is written slide for slide at its slide size: each text box, shape (its outline, fill, line, turn and mirroring, with the text in it), picture and table in its place (bounds), the slide's background colour, and its speaker notes on the slide's notes page. A chart is a table of its data in the chart's place.
  • A PDF becomes a slide for each page, at the pages' most common size (a page of another size is scaled into it, centred). Each paragraph is a text box where the page set it, its lines broken and spaced as on the page (each line on the baseline the page drew it on, where the runs' bounds.baseline give it), in its runs' fonts, sizes and colours; a paragraph set beside a floating table or picture is a box for each group of its lines. Tables keep their measured row heights and their cells' shading, pictures their places, and footnotes and a page's notes are at the foot of their page. A page's invisible text (a scan's recognised words laid over its picture, TextFormatting.invisible) is written fully transparent: not seen, still there to select and search. A table whose text is all invisible is drawn without rules (its cells' text in their places where the page gave them).
  • Any other document flows onto 16:9 slides: a slide for each heading of the first two levels, titled by it, with the text under it as bullets (lower headings bold), carried on to more slides of the same title where it does not fit. Text before the first heading is under the document's title, from its metadata. Each table is on slides of its own, ten rows a slide with its header rows repeated, and each sheet of a workbook is a table under the sheet's name. Pictures (those in a table's cells too) are on slides of their own, charts are tables of their data, a presentation's speaker notes go with the slides its content made, and footnotes and endnotes, numbered where they are cited, are listed on slides at the end.

A numbered list item carries its own number as the document shows it (2., 1.1., iv.), and a picture its alternative text. A code block is set in a monospaced font, line for line; an embedded video or page is its link; a picture known only by its address is its alternative text, and reported; comments go into the speaker notes of the slide they are on. A PDF page shown turned (/Rotate) has its text and pictures turned with it. A presentation or PDF parsed with ignorePageGeometry has no places on its pages, so it flows as any other document. Pictures and charts need extractAttachments: true on the parse (OfficeConverter.convert() sets it); PNG, JPEG, GIF and BMP pictures are written, and others are reported with IMAGE_PROCESSING_FAILED. Links to web, mail and phone addresses stay clickable. What a slide cannot hold (a chart without its data, a picture without a place on a page) is reported with CONTENT_NOT_REPRESENTABLE.

Property Type Default Description
backgrounds (Uint8Array | null | undefined)[] [] A picture (PNG or JPEG bytes) for each page of a PDF or slide of a presentation, in order, drawn as its slide's background under its text; null or undefined for one without. Give a PDF's pages drawn without their text, and the slides look as the pages did (shapes, gradients and charts included) with the text over them to edit; a page's tables are then their cells' text in place over the picture, which holds their rules. The page's pictures are placed over the background as objects of their own too, so a picture the background also holds is there twice and moving one uncovers its copy beneath. A flowing document's slides take them in order. The CLI takes picture files: --pptxConfig.backgrounds=a.png,b.png.

OdpGeneratorConfig (odpConfig)

Writes an OpenDocument presentation (a .odp zip) from the same deck as PPTX output, with the same option, and returns a Uint8Array: a presentation slide for slide, a PDF's pages as slides with their text in place, any other document flowed onto slides. A shape is drawn in ODF's own outline of its kind where it has one (rectangles, rounded rectangles, ellipses, triangles, diamonds, polygons, stars, arrows, lines), else as a rectangle, which is reported.

Property Type Default Description
backgrounds (Uint8Array | null | undefined)[] [] A picture (PNG or JPEG bytes) for each page of a PDF or slide of a presentation, in order, drawn as its slide's background under its text; null or undefined for one without. Give a PDF's pages drawn without their text, and the slides look as the pages did (shapes, gradients and charts included) with the text over them to edit; a page's tables are then their cells' text in place over the picture, which holds their rules. The page's pictures are placed over the background as objects of their own too, so a picture the background also holds is there twice and moving one uncovers its copy beneath. A flowing document's slides take them in order. The CLI takes picture files: --odpConfig.backgrounds=a.png,b.png.

TexGeneratorConfig (texConfig)

Writes LaTeX source from any parsed source. The output compiles unmodified with pdfLaTeX, XeLaTeX, LuaLaTeX, upLaTeX, pLaTeX and latex (the last three through dvipdfmx), TeX Live 2021 and later: the preamble selects fonts per engine and loads only the packages the document uses. The value is a string, or a Uint8Array zip when bundle is set. Adds no dependencies and runs identically in Node and the browser. Destination 'tex' (alias 'latex'). It is the round-trip partner of the LaTeX parser: the .tex (or the bundle zip, images included) parses back, and a generate, parse, generate cycle reaches a fixed point after one round.

Property Type Default Description
documentClass 'auto' | 'article' | 'report' | 'book' | 'beamer' 'auto' auto writes a beamer presentation for slide content (PPTX/ODP) and an article otherwise. report/book map level-1 headings to \chapter; beamer for a non-presentation source starts a frame at each level-1/2 heading.
standalone boolean true false emits only the body, headed by a comment listing the packages (and, for Greek, Cyrillic or CJK text, the font setup) the including document needs.
bundle boolean false true returns a zip of main.tex plus every image as a file under images/, ready to compile or upload to Overleaf. With false the result is the .tex alone, carrying its PNG and JPEG images inside it (see embedImages). An image the source referred to only by a plain relative path, with no image data (a .tex parsed without its project), keeps that path in \includegraphics; the IMAGES_NOT_BUNDLED warning names it in either mode, since there is nothing to carry or bundle.
embedImages boolean true Carry each PNG and JPEG image inside the .tex, so the one file compiles with its pictures. LaTeX reads images only from files, so each becomes a filecontents* block holding it as a small all-ASCII PDF (about a quarter larger than the image), named after a hash of its content; compiling writes that file beside the .tex (keeping a file of that name already there, so a picture can be replaced) and \includegraphics reads it with every engine, with no shell escape or Ghostscript. Compile in the .tex's folder: with --output-directory, pdfLaTeX and LuaLaTeX still find the files, but XeLaTeX and dvipdfmx look beside the .tex, so use bundle there. A PNG that must be decoded to be carried (transparency, interlacing) is carried up to 16 megapixels, and a document's decoded images up to 256 megapixels in all; past that it is referenced as a file. Other image formats cannot be drawn by LaTeX and appear as a labelled box. false refers to images/<name> files instead, and the IMAGES_NOT_BUNDLED warning names the files to place there. Ignored with bundle.
numberSections boolean false Number sections. Off by default, matching office documents.
format PaperFormat 'auto' Paper size, written as a geometry option. 'auto' is the document's own page, else A4; or the names pdfConfig.format accepts. Ignored by beamer.
landscape boolean false Landscape orientation. Ignored by beamer.
margin object the document's, else 72 Page margins (top, right, bottom, left), each a number of points or a unit string ('1in', '2cm', '36pt'). A side left unset is the document's own margin under format: 'auto', else 72 (one inch). Ignored by beamer.

Headings become sectioning commands with \labels, lists nested itemize/enumerate, tables longtable (or tabular where a longtable cannot go) with \multicolumn/\multirow merges (a table wider than 16 columns continues below itself in bands), footnotes/endnotes \footnote/\endnote, review comments LaTeX % comments, code lstlisting/verbatim, page headers fancyhdr, and slides beamer frames with speaker notes as \note. A bibliography is written as thebibliography, so its citations resolve; a citation with no entry is reported (CITATIONS_NOT_RESOLVED). Math loads the packages its commands come from (bm, mathtools, siunitx, ...), and a command nothing loaded defines prints its own name.

Safety. All document text is escaped, URLs are scheme-checked and percent-encoded, and image paths are reduced to safe names under images/. Math is the one place content is emitted as live LaTeX; an expression that uses a command able to read or write files, run programs or redefine commands, or that is structurally unbalanced, is written as literal text with a MATH_WRITTEN_AS_TEXT warning. A character the default fonts lack gets a fallback under every engine; a script pdfLaTeX cannot typeset is shown there as [U+XXXX] (Greek as math letters).

Engines and fonts. The preamble tells the engines apart with iftex. XeLaTeX and LuaLaTeX load fontspec, and for text in scripts Latin Modern lacks, fonts TeX Live ships: Computer Modern Unicode for Greek and Cyrillic, and Fandol, Harano Aji or UnFonts for Chinese, Japanese and Korean (whichever language the text is mostly in, the others as fallbacks) through xeCJK or luatexja, which also break lines between CJK characters. Each font is used only where it is installed, so a smaller TeX installation still compiles the document, those characters left blank. pdfLaTeX, upLaTeX and pLaTeX load 8-bit fonts; upLaTeX and pLaTeX set CJK text in their own Japanese fonts (which lack Hangul; pLaTeX before TeX Live 2023 cannot read Hangul at all). In DVI mode (latex, uplatex or platex, then dvipdfmx) a class option gives every package the dvipdfmx driver, so images, links and colours work there too.

const { value: zip } = await ast.to('tex', { texConfig: { bundle: true } });  // Uint8Array (main.tex + images/)

MetadataOverrides (metadataOverrides)

Overrides the metadata embedded in generated output, applied per field on top of ast.metadata (see the AST spec for the parsed shape), so setting one field leaves the rest of the parsed metadata intact. ast.metadata itself is never mutated, so the same AST can be generated repeatedly with different metadata.

Every field is optional. Field names mirror OfficeMetadata so the same vocabulary describes what was parsed and what gets written.

await ast.to('html', {
    metadataOverrides: {
        title: 'Q4 Report',
        author: 'Acme Inc',
        custom: { department: 'Finance', reviewed: true },
    },
});

Dates

created and modified take a Date. When modified is unset, officeParser uses the source document's own ast.metadata.modified, falling back to the current time only if the document has none. Dates outside the 1980–2099 range a ZIP timestamp can represent are clamped where EPUB writes them onto zip entries.

Not every format can represent every field

HTML <meta> tags and Markdown frontmatter are open vocabularies and accept anything. EPUB's OPF is a closed Dublin Core vocabulary and RTF's \info group has a fixed set of control words, so a custom entry has nowhere to go in either. Rather than dropping it silently, those generators report it through onWarning (OfficeWarningType.METADATA_NOT_REPRESENTABLE) and continue; the named fields still apply. Plain text and CSV only emit metadata at all when renderMetadata is on.

Style Mapping (The Semantic Bridge)

Style mapping allows you to define the semantic meaning of arbitrary document styles.

Legacy String DSL

["p[style-name='Heading 1'] => h1", "p[style='Quote'] => blockquote"]

Structured Objects (Recommended)

Use for full type safety, class application, and the ~= partial-match operator:

styleMap: [
    {
        selector: { nodeType: 'paragraph', attributes: { style: 'Heading 1' } },
        output: { tag: 'h1', classes: ['main-title'], attributes: { id: 'top' } }
    },
    {
        // '~=' matches if the word 'Quote' appears anywhere in the style name
        selector: { attributes: { style: { value: 'Quote', operator: '~=' } } },
        output: { tag: 'blockquote', fresh: true }
    }
]

fresh: true prevents the generator from merging adjacent nodes of the same tag into one block. Without it, consecutive paragraphs mapped to blockquote would be combined into a single element.

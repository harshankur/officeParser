OfficeTemplate Specification

OfficeTemplate.render() (alias renderTemplate) fills a Word (.docx) or OpenDocument text (.odt, .ott) template's tags from your data and returns a new document of its format (a .docx, or an .odt): {{placeholder}} fields, {{ if }} conditions that keep or drop content, and {{ for }} loops that repeat it, down to one table row per item. It is a lightweight mail-merge / document-generation entry point: a zero-dependency take on Adobe's Document Generation API, built on the bundled fflate.

It is not parsing or conversion: the template is copied and only its tags change, so every bit of the original formatting, layout and structure is preserved. Give it one data object for one document, or an array for a batch (one document per entry, a classic mail-merge).

OfficeTemplate.render()

import { OfficeTemplate } from 'officeparser';
import { writeFileSync } from 'fs';

// One document.
const bytes = await OfficeTemplate.render('invoice-template.docx', {
    data: { name: 'Acme Corp', amount: '$1,250.00', due: '2026-10-01' },
});
writeFileSync('invoice-acme.docx', bytes);

// A batch: one document per row (a classic mail-merge).
const docs = await OfficeTemplate.render('invoice-template.docx', {
    data: [ { name: 'Acme Corp', amount: '$1,250.00' }, { name: 'Globex', amount: '$980.00' } ],
});
docs.forEach((d, i) => writeFileSync(`invoice-${i}.docx`, d));

Passing a single data object resolves to a single Uint8Array; passing an array resolves to a Uint8Array[], one per entry, all from the same parsed template.

Arguments

Argument Type Description
template string | Buffer | ArrayBuffer | Uint8Array | Blob The template file path (Node) or its bytes. Same input shapes as parseOffice.
config TemplateConfig The data and options below. data is required.

TemplateConfig

Property Type Default Description
data TemplateData | TemplateData[] required Field values. One object → one document; an array → one document per entry. A value may be a string, number, boolean, Date (rendered as ISO), null/undefined (rendered empty), a list (what a for loop repeats over) or an object (whose fields a path reads).
fileType 'docx' | 'odt' | 'ott' (none) Optional format hint. The format is always read from the bytes; the hint only words the unsupported-format error when a template of another format is passed.
delimiters { start: string; end: string } {{ }} Tag delimiters, for fields and block tags alike. Custom delimiters may contain any characters, including quotes (e.g. { start: '[[', end: ']]' } makes [[ if paid ]] a block tag).
onMissing 'keep' | 'empty' | 'error' 'keep' A field the data does not have, in a placeholder, a condition or a loop's list: 'keep' leaves it as typed (a placeholder's text stays, formatting of its runs preserved; a block whose condition or list uses the field is left exactly as typed, tags and content included), 'empty' treats it as empty (blank text, null in a condition, a loop of nothing), 'error' rejects with TEMPLATE_FIELD_MISSING. A field that is present but null/undefined always renders empty.
numberSeparators { decimal?: string; group?: string } { decimal: '.', group: ',' } What a number picture writes for its point and groups ({ decimal: ',', group: '.' } writes 1.250,50).
dataNumberSeparators { decimal?: string; group?: string } (none) How a number written as text in the data is read, by a number picture and where a condition compares it with a number: { decimal: ',', group: '.' } reads 12,50 and 1.234,50. Each separator is one character (group may be '', the default, for none; decimal defaults to .); a space group separator matches a no-break space too. A group separator must be followed by groups of three digits, so an ambiguous text (1.5 with . for groups) is no number rather than a wrong one (nor is 0.500: a first group never starts with 0). Not given, text is read as before: . for the point and no groups (1250.5). numberSeparators says how numbers are written, this how they are read.
dateNames TemplateDateNames English The month and day names (full and short) and the AM/PM markers a date picture writes.
utcOffsetMinutes number 0 Minutes added to UTC before a date picture writes a date (330 for India). A fixed offset, the same on every machine.
formatters Record<string, TemplateFormatter> (none) Filters of your own, used after | in a tag ({{ name | initials }}).
password string (none) Decrypts the template first if it is itself password-protected (encrypted OOXML). A missing/wrong password rejects with PASSWORD_REQUIRED/PASSWORD_INCORRECT.
onPassword (reason) => string | undefined (none) Called (with 'required' or 'incorrect') when password did not decrypt the template, to supply one lazily; return a password to retry, or undefined to give up. Same capped-retry behaviour as the parser's onPassword.
maxPasswordAttempts number 3 How many times onPassword is asked before the render rejects with PASSWORD_REQUIRED/PASSWORD_INCORRECT, as the parser's option of the same name.
onWarning function undefined Callback for non-fatal issues (receives an OfficeIssue). Also suppresses the console fallback, so a thrown rejection is not additionally printed.
decompressionLimits DecompressionLimits (none) Bounds unzipping of an untrusted template exactly as parsing does; a zip-bomb template rejects with a typed ZIP_* error rather than being mistaken for a non-DOCX file. Its maxXmlElements (2,000,000) bounds the elements the template's parts hold, as for parsing, and its tags and the tokens they hold (operands, filters, picture parts) with them. Its maxRepeatedContent (16 MiB) bounds what a document adds by repetition: each copy of a loop's content after its first, each copy of a note a repeated reference points at, each use of a value after its first (what the value outgrows its placeholder by), each block or field written again as typed, and each field, loop or branch evaluated (a few characters, plus its condition's size). Past it the render rejects with OUTPUT_TOO_LARGE.

OfficeTemplate.tags() and OfficeTemplate.check()

// What the template reads: each field, and each tag opening a block or branch, in the order of each part
// (and text that looks like a tag but is not one, as kind 'text').
const tags = await OfficeTemplate.tags('invoice-template.docx');

// Check data before rendering: every problem a render with onMissing: 'error' would reject for.
const problems = await OfficeTemplate.check('invoice-template.docx', { data });
if (problems.length === 0) await OfficeTemplate.render('invoice-template.docx', { data });

Text that looks like a tag

Text a person meant as a tag that is not one is listed by tags() as kind: 'text', in its place among the tags (its part, its loops, no fields), and render() and check() report it once per call with a TEMPLATE_NOT_A_TAG warning whose details.texts holds each one's text, part and reason, and details.found how many there are. At most 1,000 such texts are listed for a template, by tags() and in the warning: past them they are only counted, the warning's message says how many were found, and tags() reports the warning when its list was cut. A render writes it as typed. It is found in every part a tag can be in: body, headers, footers, notes, comments, text boxes. Exactly these count (TemplateTextReason):

reason What Example
space-in-nameText between the delimiters that is a name with white space in it: letters, digits, _ . - and white space, starting with a letter or _, at most 64 characters.{{first name}}
unknown-filterA field through a word after | that is no filter, built in or in formatters.{{ total | fromat "0.00" }}
missing-delimiterFor delimiters of one character typed twice or more (the default), a name between delimiters one of which is a character short. A short start inside braces still open, or a short end whose brace a later one closes (code nesting them), is not reported.{{ name }, { name }}
full-widthA name between delimiters typed with full-width characters (U+FF01 to U+FF5E), as a Japanese or Chinese keyboard types them.｛｛nom｝｝

Never reported: a single brace, {x}, { x }, JSON ({"a": {"b": 1}}), code that nests braces ({a: {b}}), an empty {{}}, prose that starts like a block tag (the pairing errors name it where it matters), and with single-character delimiters ($) anything but a name with spaces.

check(template, config) reads config.data as a render with onMissing: 'error' reads it, whatever onMissing says, without writing a document: each field, condition and loop the data leads to, every pass of every loop, and the branch each condition picks (a field only another branch uses is not needed). Where a render would reject, the problem is noted and the check goes on past that tag: a branch or loop whose condition or list is missing or does not fit is not entered, so the fields inside it are checked once it is given. A key present but undefined or null counts as given. One data object resolves to TemplateProblem[]; an array to one list per entry. At most 1,000 problems are listed for an entry and 10,000 for a batch: past them the check stops with a TEMPLATE_CHECK_LIMITED warning, and a batch's later entries get empty lists. A template's own errors, the limits a render is held to, and an error a filter of your own throws reject as a render's do.

code'TEMPLATE_FIELD_MISSING' | 'TEMPLATE_DATA_INVALID'A field the data does not have, or a value that does not fit its tag.
messagestringWhat a render would say.
fieldstringFor a missing field: the field as typed.

Conditions and loops

Block tags are typed in Word as ordinary text, between the same delimiters as fields:

{{ if paid }}
Paid in full. Thank you!
{{ else if total > 1000 }}
Please pay {{ amount }} by {{ due }}. Large invoices may be paid in instalments.
{{ else }}
Please pay {{ amount }} by {{ due }}.
{{ endif }}

{{ for line in lines }}
{{ line.description }} x {{ line.qty }}: {{ line.price }}
{{ endfor }}

What a block covers

Where its tags sit decides what a block covers. A block is exactly the content between its tags:

Tags The block covers
In one paragraph The text between them: {{ for t in tags }}{{ t }}{{ if not loop.last }}, {{ endif }}{{ endfor }} writes red, blue.
In separate paragraphs The paragraphs between them. When every tag of the block has a paragraph of its own, those paragraphs are removed with the tags, so no blank line is left; a tag sharing its paragraph with text cuts the paragraph where it stands, and the block's other tag paragraphs then stay, empty.
In different cells of one table Whole rows, from the row of the opening tag to the row of the closing tag. A row with {{ for line in lines }} in its first cell and {{ endfor }} in its last repeats once per line; tags in two rows repeat the two as a group. An {{ if }} keeps or drops rows the same way, each else starting a row of its own.

In an ODT, tags in items of one list cover the items between them, a tag's item going with it when the tag is all it holds; rows inside a table's heading rows (table:table-header-rows) repeat there, and rows in table:table-rows or a row group widen to it.

Tags that cannot enclose content together (one in a table and the other outside it, one in a text box, note or comment and the other not, one inside a tracked change, one in a Word field and the other outside it, one in a table's heading rows and the other in its body, two at different levels of a list) reject with TEMPLATE_SYNTAX rather than writing broken XML. A text box holds blocks of its own, in any of the three scopes.

Text that starts like a block tag but is not one ({{ If you have questions, call us }}) stays text, as prose between the delimiters always has. When the blocks around it then fail to pair, the error names it and why it could not be read: {{ if a = 1 }}x{{ endif }} rejects naming {{ if a = 1 }}, which compares with a single =.

Conditions

  • A condition is a field ({{ if paid }}) or a comparison: ==, !=, <, <=, >, >=, joined with and, or, not and parentheses, against numbers, quoted strings, true, false and null.
  • false, null, "", 0, an empty list and an invalid date count as false; everything else, the text "0" included, as true.
  • A comparison takes two values of the same kind (two numbers, two strings, two dates, two booleans) or an empty one, which equals only another empty one and is never less or greater. Text that is a number, compared with a number, compares as that number ({{ if total > 100 }} with total: '250', as a form or a spreadsheet gives it), read with dataNumberSeparators when set; other text compared with a number ("150 EUR") rejects with TEMPLATE_DATA_INVALID rather than silently picking a branch. Two texts compare as text.
  • Keywords are case-insensitive ({{ If paid }}, as AutoCorrect may capitalize it), and a string may be quoted with straight or curly quotes, which AutoCorrect writes in Word.

Loops and data

  • A loop names its item: {{ line.price }} in a list of objects, {{ t }} in a list of plain values. Inside a loop, loop.index (from 0), loop.number (from 1), loop.first, loop.last and loop.length describe the current pass, for the innermost loop. The item's name hides a field of the same name inside the loop.
  • Loops and conditions nest, up to 64 blocks deep.
  • A path reads nested data: {{ customer.address.city }}, {{ items.0.name }}, {{ items.length }}. A top-level key that itself holds a dot ("invoice.total") is read as typed before it is read as a path. Only the data's own keys are read, never __proto__, constructor or toString.
  • Copies of pictures, bookmarks (their names too), paragraphs and content controls get fresh ids, as Word requires unique ones, and a footnote, endnote or comment in a copy gets a copy of its own in its part, filled in for that pass, so a field in it reads the pass's item. A table a loop or a branch left with no row is removed, and a cell or content control left without a paragraph gets an empty one.
  • In an ODT, copies get fresh xml:ids and draw:ids (one value per element, and the half of a span, link or meta after a block's cut through it gets one too), note ids, and names for bookmarks, reference marks, index marks, comments, frames, tables and sections (a range's end follows its start; a range across a loop's edge is written once, and a comment in the loop is still copied with each pass, the later copies on a point). Notes, comments and text boxes live in their paragraph and are copied with it, reading the pass's item. A table or group of rows left with no row is removed; a cell, header, footer, note, text box or comment left with no paragraph keeps an empty one; a bookmark range whose end a branch removed is closed at its start, and an end whose start went is removed.

Formatting values

A field can be written through filters after |. format takes a picture, as Word's own mail merge does (its \# and \@ switches; Excel's number formats read number pictures the same way, apart from its thousands scaling, a comma after the last digit, which a picture rejects):

{{ total | format "$#,##0.00" }}              $1,250.50
{{ total | format "#,##0.00 '€'" }}           1,250.50 €
{{ loss | format "$#,##0.00;($#,##0.00)" }}   ($320.00)
{{ rate | format "0.0%" }}                    12.5%
{{ due | format "MMMM d, yyyy" }}             November 1, 2026
{{ name | upper }}                            ADA LOVELACE
  • Number pictures: 0 (a digit, always written), # (a digit, written when there is one), , (groups of three), . (the point), % (a percentage); up to three sections, positive;negative;zero; text in 'quotes' or after \ is written as is. Values are rounded half away from zero, as Word and Excel do; text that is a number is taken too, read with dataNumberSeparators when set ("1.234,50").
  • Date pictures: d–dddd, M–MMMM, yy, yyyy, h/hh (12-hour), H/HH, m/mm, s/ss, AM/PM (am/pm, A/P). As in Word, M is the month and m the minute: Excel's dd/mm/yyyy is dd/MM/yyyy here. A value is a Date or ISO 8601 text (UTC when it has no offset).
  • The same on every machine: the formatting is officeParser's own, not the runtime's Intl. numberSeparators, dateNames and utcOffsetMinutes set what it writes.
  • upper and lower change case; filters chain left to right; formatters adds filters of your own, each given the value as the data holds it and the strings and numbers after its name.
  • A picture given the wrong kind of value rejects with TEMPLATE_DATA_INVALID (unformattable); a picture that cannot be read with TEMPLATE_SYNTAX. A word after | that is no filter leaves the tag as text. An empty value stays empty; a missing one follows onMissing.

Errors

Code details.reason When
TEMPLATE_SYNTAX unreadable, unclosed, unopened, mismatched, else-after-else, crossing, row-branch, overlap, malformed-xml Blocks do not pair: a block is never closed, a closing tag or else has no block, or a closing tag closes another kind of block (where a tag that could not be read is why, it is named, with unreadable); or a block's tags cannot enclose content together. details.tag is the tag as typed and details.part the part holding it. A block keyword spelt as other template languages spell it (elseif, elsif, elif, end if, end for) is refused at once, with details.suggestion: the tag as it should be typed ({{ else if x }}, {{ endif }}), its spacing kept.
TEMPLATE_DATA_INVALID not-a-list, not-text, incomparable, unformattable A value does not fit its tag: a loop over something that is not a list, a list or object placed as a field, a comparison of two kinds of value. details.kind (and otherKind) name the values' kinds.
TEMPLATE_FIELD_MISSING A field the data does not have, under onMissing: 'error'.
MAX_NESTING_DEPTH_EXCEEDED Blocks nest more than 64 deep.

How substitution works

  • Run-aware. Word often splits a typed {{name}} across several runs ({{, na, me}}), and LibreOffice across spans; it is filled anyway, and a value adopts the formatting of the run its placeholder began in (a bold {{amount}} renders bold). Block tags are found the same way. In an ODT, spaces kept as <text:s/> read as the spaces they stand for (a run of more than 16 is read as 16, and written back whole).
  • Everywhere text lives. Tags in the body, headers, footers, footnotes/endnotes, comments and text boxes are all filled. Deleted text kept for tracked changes, and in an ODT the text of fields, note citations and comment authors, is not read.
  • Field names are Unicode letters and digits plus _, ., - (e.g. {{invoice.total}}, {{customer-name}}). if, else, endif, for and endfor are the block tags' own words. Other text between the delimiters, such as prose with spaces, is left as literal text, so it is never mistaken for a field.
  • Values are XML-escaped; a newline (\n, \r\n, a lone \r, or the Unicode line/paragraph separators) becomes a real line break; XML-illegal control characters are stripped. In an ODT, a tab is a <text:tab/> and a run of spaces is kept with <text:s/>.
  • Deterministic. The same template + data renders byte-identical output (pinned zip timestamps), in any timezone.
[!NOTE] Templating supports Word (.docx) and OpenDocument text (.odt, and .ott, which renders to an .odt: its mimetype and its manifest's root media type say so, nothing else in the manifest or meta.xml changes). An ODT is written as OpenDocument requires, mimetype first and stored. An encrypted template is decrypted with password or onPassword, and the document written is plain. Another format rejects with TEMPLATE_UNSUPPORTED_FORMAT.
[!TIP] Reuse one template across a batch by passing an array to data: the template is unzipped and its tags read once (every tag error is raised before any document is rendered), then each row is rendered from the shared copy.

OfficeTemplate Specification

OfficeTemplate.render() (alias renderTemplate) fills a DOCX template's {{placeholder}} tags from your data and returns a new .docx. It is a lightweight mail-merge / document-generation entry point: a zero-dependency take on Adobe's Document Generation API, built on the bundled fflate.

It is not parsing or conversion: the template is copied and only its placeholders are substituted, so every bit of the original formatting, layout and structure is preserved. Give it one data object for one document, or an array for a batch (one document per entry, a classic mail-merge).

OfficeTemplate.render()

import { OfficeTemplate } from 'officeparser';
import { writeFileSync } from 'fs';

// One document.
const bytes = await OfficeTemplate.render('invoice-template.docx', {
    data: { name: 'Acme Corp', amount: '$1,250.00', due: '2026-10-01' },
});
writeFileSync('invoice-acme.docx', bytes);

// A batch: one document per row (a classic mail-merge).
const docs = await OfficeTemplate.render('invoice-template.docx', {
    data: [ { name: 'Acme Corp', amount: '$1,250.00' }, { name: 'Globex', amount: '$980.00' } ],
});
docs.forEach((d, i) => writeFileSync(`invoice-${i}.docx`, d));

Passing a single data object resolves to a single Uint8Array; passing an array resolves to a Uint8Array[], one per entry, all from the same parsed template.

Arguments

Argument Type Description
template string | Buffer | ArrayBuffer | Uint8Array | Blob The template file path (Node) or its bytes. Same input shapes as parseOffice.
config TemplateConfig The data and options below. data is required.

TemplateConfig

Property Type Default Description
data TemplateData | TemplateData[] required Field values. One object → one document; an array → one document per entry. A value may be a string, number, boolean, Date (rendered as ISO), or null/undefined (rendered empty).
fileType 'docx' (none) Optional format hint. Only 'docx' is currently supported; it is surfaced in the unsupported-format error message when a non-DOCX template is passed.
delimiters { start: string; end: string } {{ }} Placeholder delimiters. Custom delimiters may contain any characters, including quotes (e.g. { start: '[[', end: ']]' }).
onMissing 'keep' | 'empty' | 'error' 'keep' A placeholder with no matching field: 'keep' leaves the tag text in place (formatting of its runs preserved), 'empty' blanks it, 'error' rejects with TEMPLATE_FIELD_MISSING. A field that is present but null/undefined always renders empty.
password string (none) Decrypts the template first if it is itself password-protected (encrypted OOXML). A missing/wrong password rejects with PASSWORD_REQUIRED/PASSWORD_INCORRECT.
onPassword (reason) => string | undefined (none) Called (with 'required' or 'incorrect') when password did not decrypt the template, to supply one lazily; return a password to retry, or undefined to give up. Same capped-retry behaviour as the parser's onPassword.
onWarning function undefined Callback for non-fatal issues (receives an OfficeIssue). Also suppresses the console fallback, so a thrown rejection is not additionally printed.
decompressionLimits DecompressionLimits (none) Bounds unzipping of an untrusted template exactly as parsing does; a zip-bomb template rejects with a typed ZIP_* error rather than being mistaken for a non-DOCX file.

How substitution works

  • Run-aware. Word often splits a typed {{name}} across several runs ({{, na, me}}); it is filled anyway, and a value adopts the formatting of the run its placeholder began in (a bold {{amount}} renders bold).
  • Everywhere text lives. Placeholders in the body, headers, footers, footnotes/endnotes and comments are all filled.
  • Placeholder names are Unicode letters and digits plus _, ., - (e.g. {{invoice.total}}, {{customer-name}}). A name containing a space or other punctuation is not recognized and is left as literal text, so ordinary prose between the delimiters is never mistaken for a field.
  • Values are XML-escaped; a newline (\n, \r\n, a lone \r, or the Unicode line/paragraph separators) becomes a real line break; XML-illegal control characters are stripped.
  • Deterministic. The same template + data renders byte-identical output (pinned zip timestamps), in any timezone.
[!NOTE] Templating currently supports DOCX (.docx). The run-aware substitution generalizes to the other OOXML/ODF text formats and they will follow. A non-DOCX template rejects with TEMPLATE_UNSUPPORTED_FORMAT.
[!TIP] Reuse one template across a batch by passing an array to data: the template is unzipped and parsed once, then each row is rendered from the shared copy.

Reports and newsletters put boxes beside their text: a sidebar, a pull quote, a note in a shaded frame on the right while the paragraph runs down its left. Word calls it a text box, LibreOffice a frame. Until 8.3.0, officeParser read the box's text and put it in the flow, where it was drawn as one more paragraph. ODT's was worse: its text was glued to the paragraph it stood in, so the paragraph read Text in a floating frame on the right.A paragraph beside a floating text frame.

Putting the box back where it stands took two halves: reading where each format says the box is, and teaching the native PDF engine to set lines of text round it. This post is about both.

Three Formats, One Box

I made one document with one frame (2.2 inches wide, 1 inch tall, 4.2 inches from the left of the text column, at the top of its paragraph, with text running beside it) and saved it from LibreOffice as ODT, DOCX and RTF. Each says the same thing in its own units and its own words.

ODT writes the frame inside the paragraph it is anchored to, in inches, with how text goes round it in a graphic style: 

<text:p><draw:frame text:anchor-type="paragraph" svg:x="4.2in" svg:y="0in"
        svg:width="2.2004in" svg:height="1.0004in" draw:style-name="gr1">
    <draw:text-box><text:p>Text in a floating frame on the right.</text:p></draw:text-box>
</draw:frame>A paragraph beside a floating text frame. ...</text:p>

<style:graphic-properties style:wrap="parallel" style:horizontal-pos="from-left"
        style:horizontal-rel="paragraph" style:vertical-rel="paragraph" .../>

Word puts a drawing in a run of the paragraph, measured in EMUs (914,400 to the inch, 12,700 to the point), with what each offset is measured from: 

<wp:anchor distT="0" distB="0" distL="0" distR="0" ...>
  <wp:positionH relativeFrom="column"><wp:posOffset>3840480</wp:posOffset></wp:positionH>
  <wp:positionV relativeFrom="paragraph"><wp:posOffset>635</wp:posOffset></wp:positionV>
  <wp:extent cx="2011680" cy="914400"/>
  <wp:wrapSquare wrapText="bothSides"/>
  ... <wps:txbx><w:txbxContent> the box's paragraphs </w:txbxContent></wps:txbx>

RTF writes a shape in twips (twenty to the point), with its wrapping as a number and its colours as integers in blue, green, red order: 

{\shp{\*\shpinst\shpleft6048\shptop0\shpright9215\shpbottom1439\shpwr2
  {\sp{\sn fillColor}{\sv 13606770}}{\sp{\sn lineColor}{\sv 10773812}} ...
  {\shptxt Text in a floating frame on the right.\par}}}

3,840,480 EMUs, 6,048 twips and 4.2 inches are all 302.4 points. That agreement is the whole job of the readers: each turns its format's words into one shape, a drawing node holding the box's paragraphs, with ShapeMetadata.float saying where it stands. Here is what each of the three files reads as: 

import { parseOffice } from 'officeparser';

const ast = await parseOffice('layout.docx');
const frame = ast.content.find(node => node.type === 'drawing' && node.metadata?.float);
console.log(frame.metadata.float);
// {
//   horizontalFrom: 'column', verticalFrom: 'paragraph',
//   x: 302.4, y: 0.05, width: 158.4, height: 72, wrap: 'beside'
// }

The ODT gives x: 302.4 too (its sizes a fraction larger, as LibreOffice wrote them), and the RTF the same again, with the 9-point gap its shapes keep from text by default. The drawing node comes just before the paragraph it is anchored to, whichever format it came from. That order is what lets a writer place the box before it lays out the lines that go round it. Writers that have no place to put a box (Markdown, plain text, a spreadsheet) write its paragraphs where it stands, so no text is lost; with ignorePageGeometry, the box is read as it was before.

Setting Lines Round a Box

The native engine lays text out one line at a time, from the top of the page down. A box changes that in one place: before a line's first word is placed, the engine looks for boxes on the page that overlap the band the line will take, and works out how much room is left beside each.

  • Text takes the side with more room. A box near the right edge leaves the left for the text.
  • If that room is less than 36 points, or a third of the line, the line moves down below the box instead of squeezing a word or two into a sliver.
  • A box set to keep text above and below it (Word's wrapTopAndBottom, ODT's style:wrap="none") sends the line below it whatever the room.
  • A box set in front of or behind the text (Word's wrapNone) is drawn and the lines ignore it, as Word draws them.

What a Box Cannot Do

Text that is already on the page cannot go round anything. Most boxes are measured from their own paragraph, so the engine meets the box just before the lines that go round it. But a box can be measured from the page or the margin, or placed above its paragraph with a negative offset, and then it stands over lines the engine has already set. My first version simply drew it there, over them.

A review round I run before every release found that, and two more of the same family. A box whose text needed more than a page lost what did not fit, because a box belongs to one page. And a table starting just above a box grew down through it, because blocks other than text only checked for a box where they start. Now:

  • A box that would stand over text already laid out stands at its paragraph instead, so the text after it goes round it and nothing is hidden.
  • A box whose text is more than a page holds is set in the flow, all of it.
  • A table, a picture, code or a chart that would reach a box below it is measured first and starts below the box.
  • Footnotes at the foot of the page are not set round boxes.

Each of these trades a little fidelity for never losing text. A word processor would reflow the page so the earlier lines go round the box as well. A layout engine that sets lines once, top to bottom, cannot, and the honest answer is to move the box rather than cover what is there.

Where It Falls Short

  • Text goes down one side of a box. Word's wrapText="bothSides" can run text down both sides of a box in the middle of a column; officeParser uses the wider side.
  • A box aligned to the middle or bottom of its page or paragraph is placed at the top.
  • Pictures floating beside text (as opposed to text boxes) are still drawn in the flow.
